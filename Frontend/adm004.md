# Kế hoạch thiết kế Chức năng Nhập liệu Nhân viên (ADM004)

Tài liệu này đặc tả hướng triển khai cho cả chức năng **Thêm mới (Add)** và **Chỉnh sửa (Edit)** nhân viên trên cùng một giao diện ADM004.

## 1. Backend (Spring Boot)

### 1.1. API & Payload
- **Thêm mới (Add)**: `POST /api/employees` - Payload `EmployeeRequest`.
- **Cập nhật (Edit)**: `PUT /api/employees/{id}` - Payload `EmployeeRequest`.
- **Lấy thông tin chi tiết**: `GET /api/employees/{id}` - Trả về dữ liệu để pre-fill vào form Edit.
- **Danh sách chứng chỉ**: `GET /api/certifications` - Để lấy danh mục chứng chỉ cho dropdown.

### 1.2. Logic xử lý
- **Validation**: Tái sử dụng logic kiểm tra từ bước 1.1 đến 1.9 cho cả Add và Edit.
- **Transaction**: Sử dụng `@Transactional` để đảm bảo lưu đồng thời vào bảng `employees` và `employees_certifications`. Khi Edit, cần xóa các bản ghi chứng chỉ cũ và insert lại (hoặc update) để đồng bộ.

## 2. Frontend (Next.js)

### 2.1. Cấu trúc Tệp tin
- **Page**: `app/(protected)/employees/adm004/page.tsx`
  - URL hỗ trợ cả `?id=...` (Edit) hoặc không (Add).
- **Hook**: `hooks/useAdm004.ts`
  - Quản lý trạng thái form (Add/Edit mode).
  - Tích hợp **sessionStorage** qua bộ helper:
    - Lưu dữ liệu form CHỈ khi nhấn nút "確認" (Nơi gọi `putSessionData`).
    - Khôi phục dữ liệu khi quay lại từ ADM005 nhưng sẽ XÓA session ngay sau khi đọc (để nếu người dùng Refresh trang thì dữ liệu sẽ mất).
    - Xóa dữ liệu hoàn toàn khi nhấn nút "戻る" tại ADM004 để về màn danh sách.
- **Component**: `components/employees/EmployeeInputForm.tsx`
  - Chứa UI form dùng chung cho cả hai chức năng.
  - Sử dụng **React Hook Form** kết hợp với **Zod** để thực hiện validation tại Frontend.

### 2.2. Logic Nghiệp vụ Persistence (Đã cập nhật)
1. **Tại ADM002 (Danh sách)**: 
    - Trạng thái tìm kiếm, phân trang, sắp xếp được lưu trực tiếp trên **URL Parameters** (ví dụ: `?name=...&dept=...&page=...`).
    - Việc này giúp người dùng có thể Refresh trang hoặc chia sẻ liên kết mà không mất kết quả tìm kiếm.
    - Không sử dụng `sessionStorage` cho màn hình này.
2. **Tại ADM004 (Nhập liệu)**: 
    - Nhấn "確認" -> Lưu vào session -> Tới ADM005.
    - Nhấn "戻る" -> Về ADM002.
3. **Tại ADM005 (Xác nhận)**:
    - Nhấn "OK" -> Lưu DB -> Xóa session -> Tới ADM006.
    - Nhấn "戻る" -> **Giữ session** -> Về ADM004 (kèm `mode=back`).
4. **Tại ADM004 (Sau khi Back từ ADM005)**:
    - Form **được khôi phục dữ liệu từ session**.
    - **Session bị xóa ngay sau khi khôi phục** để đảm bảo tính tạm thời.
5. **Refresh trang (F5) tại ADM004**: 
    - Dữ liệu form sẽ mất (vì session đã bị xóa sau khi khôi phục hoặc chưa từng lưu).


### 2.3. Tầng API (`lib/api/employee.api.ts`)
- `addEmployee(data)`: POST request.
- `updateEmployee(id, data)`: PUT request.
- `getEmployee(id)`: GET request.
- **Mới**: `getCertifications()`: GET request tới `/api/certifications`.

## 3. Quy định về Coding Convention
- **Comment**: Áp dụng Header Comment và Javadoc-style cho tất cả các hàm và component mới theo phong cách hiện tại của dự án (Copyright, Author, Description).
- **Cấu trúc**: Tuân thủ mô hình UI -> Hook -> API. Logic nghiệp vụ không được đặt trực tiếp trong file Page hoặc Component giao diện.

---

## 4. Quy trình triển khai
1. **API `/certifications`**: Triển khai trước để lọc danh sách chứng chỉ trên UI.
2. **Unified Form**: Xây dựng `EmployeeInputForm.tsx` với các validation client-side cơ bản.
3. **Logic Chỉnh sửa**: Xử lý logic tải dữ liệu cũ khi có `id` trên URL.
4. **Persistence**: Tích hợp `sessionStorage` vào hook để xử lý kịch bản Refresh và nút "Back" từ màn xác nhận.
